## applicability

当前方案依赖尚未验证的关键假设，直接完整实施可能造成大量返工。

已有充分证据支持该假设时，无需重复组织验证。普通的小范围修改不必专门采用。

## evolution

1. 检查现有证据，以及是否已有 Context 正在负责相同验证；能够复用时继续已有工作。
2. 证据不足且需要独立考察时，提出最小验证工作。明确具体假设、判断标准，以及可复现实验、日志或其他可检查证据。
3. 依赖该假设的实施等待真实验证结果。不依赖该假设的工作，在条件允许时继续推进。
4. 结果发布后，假设成立则在验证范围内继续实施；不成立则保留失败证据并调整方案；证据不足则说明缺少什么，避免重复相同验证。
5. 将真实结论带回相关工作。所需结论已经充分时停止扩张验证，整体任务由既有验收机制确认。

## inheritance

验证工作继承待验证假设及成立条件、用户目标、最新有效约束、验收要求，以及必要材料及其版本和相关证据。

不继承与验证无关的完整讨论过程。未经验证的判断保留为假设，不能当作事实。

后续实施继承真实验证结论、证据来源和适用范围。失败结果作为排除依据保留，已被否定的方案不再作为有效计划。
