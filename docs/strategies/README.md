# Strategy · 工作策略

**你只管目标与反馈，让 Focus 按你的方法组织工作。**

Strategy 是一份可分享的上下文演化方法：规定什么工作局面下，如何组织、调整和汇合 Context，以及各项工作应该继承什么。用户可以编写、安装、编辑和分享方法，日常仍通过 Patrol 的单入口表达目标与反馈。

| 内容 | 职责 |
| --- | --- |
| Memory | 需要记住的事实、决定和约束 |
| Skill | 一项具体工作的完成方法 |
| Strategy | 整体工作的推进方式和上下文组织方法 |

## 接入自己的策略

进入 **记忆库 → Strategy · 工作策略**：

- **新建策略**：填写名称、三段正文和范围。ID 留空时自动生成稳定的 `local/<identity>`，也可以填写 `your-name/your-method`。
- **导入策略**：选择 `STRATEGY.md` 或粘贴内容，选择全局或工作区，预览后安装。
- **提炼策略**：在策略编辑器填写工作经验生成草稿；或在记忆整理器选择实际工作材料，点击“从所选材料提炼策略”。草稿经过编辑并保存后才进入安装列表。
- **分享策略**：选中策略，点击“导出 STRATEGY.md”。导出当前编辑内容，不包含本地路径、工作区身份、启用设置和本地条目 ID。

用户可以直接说“这次按‘先验证关键假设’推进”，也可以只表达目标。策略只影响工作安排，不要求用户操作 Context ID 或手动分配线程。

## v1 文件格式

```markdown
---
schema: focus.strategy/v1
id: your-name/your-method
name: 你的方法
description: 一句话介绍方法的作用
version: 1.0.0
---

## applicability

什么局面适用，需要什么前提，什么时候无需采用。

## evolution

如何继续或派生工作，等待什么真实结果，反馈到来后怎样调整，何时汇合和停止。

## inheritance

各项工作继承什么、排除什么，如何保留来源、版本和不确定性。
```

- `schema`、`id`、`name`、`version` 必填，`description` 可选。
- ID 使用小写 ASCII 命名空间和名称，以 `/` 分隔，允许数字、点、下划线和连字符。身份是分享标识，不代表发布者经过验证。
- 三段正文每段最多 12000 字符；文件最多 160000 UTF-8 字节；元信息最多 8000 字符。
- 正文以三个准确的二级标题分段，章节顺序可调整，章节内可包含子标题和代码块。
- 不接受重复章节、重复元信息键、YAML alias、未知元信息字段或不支持的 schema。正文中的命令只作为方法材料，不会在安装时执行。
- 文件格式版本与作者发布版本分别演进。同一方法升级沿用 ID，另创方法使用新 ID。

## 作者写作约定

一份策略需要解释为什么这样组织工作，而不只是给 Agent 角色命名。

1. 写清适用和不适用条件。一次普通修改可以继续已有 Context。
2. 派生时说明独立思考历史的价值；已有工作能承担时优先复用。
3. 前置结果尚未出现时，不能提前声称已经得到结论。需要强制保证的顺序必须落实为任务约束和可验证证据前提，策略文字本身不提供执行保证。
4. 独立验证继承目标、材料和评价条件，避免将待验证推断当作事实。
5. 反馈到来后重新判断安排；被替代要求不继续作为有效要求。
6. 汇合时保留来源、差异和未决问题；证据已经足够时停止扩张。

策略不单独保存任务进度。每轮以实际工作进展、用户反馈和真实结果重新判断。

## 作者预演

编辑器的“用三个场景预演方法”接受三个具体场景：

| 场景 | 检查重点 |
| --- | --- |
| 预期应该采用 | 是否产生有价值的工作安排、继承规则与停止条件 |
| 预期不必采用 | 能否继续已有工作，避免为策略名称制造新 Context |
| 收到新反馈后 | 能否调整依赖和继承材料，排除过时要求 |

预演调用当前配置模型，只生成推演，不读取或修改真实任务，也不提供真实执行或验收保证。场景标签是作者预期，模型可以判断策略不适用。修改正文或场景后，旧预演结果失效。

## 安装、覆盖与更新

安装表示拥有一份方法；启用表示允许考虑；实际采用表示方法影响了本轮的具体安排。

- 全局策略适用于各工作区；工作区同 ID 安装整份覆盖全局安装，包括停用设置。
- 先解析作用域覆盖，再筛选启用策略。工作区停用不会让全局版本重新生效。
- 相同 ID、范围和正文的重复导入不会新增条目，也不会改变现有启用设置。
- 不同内容的导入展示当前安装与待导入正文，明确选择替换，或另存新 ID 后编辑。同版本不同正文也按冲突处理。
- 本地编辑标记“本地已修改”。替换前会核对预览时的安装哈希，预览后发生变化则需要重新预览。
- 修改、升级和停用从后续新冻结轮次生效；不会修改正在使用的快照及历史决策。
- `version` 用于发布说明，实际运行内容通过冻结快照及哈希追溯。

## 实际采用记录

Patrol 的 `strategy_adoptions` 仅记录实际采用的方法：`memory_id`、冻结的 `content_hash`、`reason` 和从 0 开始的 `action_indexes`。

模型合同和 Kernel 分别验证引用属于本轮冻结集合、没有重复，且动作索引有效。记录随决策持久化，通过轮次事件、实时快照和审计接口返回。界面中的名称和版本从当时的冻结快照解析，不查询后来修改的安装。

## HTTP 接口

接口沿用桌面会话认证。

| 接口 | 请求 / 返回 |
| --- | --- |
| `POST /desktop/api/strategies/preview` | `{markdown, workspace_id?}` → 元信息、三段正文、内容哈希及同范围现有安装 |
| `POST /desktop/api/strategies/install` | `{markdown, workspace_id?, enabled?, replace_memory_id?, expected_hash?}` → 状态及安装条目 |
| `GET /desktop/api/strategies/{memory_id}/export` | `{filename, markdown}` |
| `POST /desktop/api/strategies/draft` | `{selection: {sources: [...]}, model_name?}` → `{title, strategy}` 草稿 |
| `POST /desktop/api/strategies/rehearse` | `{title, strategy, scenarios: {applicable, inapplicable, feedback}, model_name?}` → 三个推演结果 |

已有 `/desktop/api/memory` 创建和更新接口继续使用，策略包元信息放在 `strategy_package`，不混入三段 `strategy` 对象。

v1 支持文件和粘贴导入。远程链接获取、自动更新、市场和可执行策略包不在本版范围内。
