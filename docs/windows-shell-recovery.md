# Windows Shell 异常恢复

Shell 进程树退出未确认时，Focus 保留 Run、派发和工作区租约。重启应用或租约到期不会自动解除这道屏障。

在 **设置 → 通用 → Shell 异常恢复** 查看受影响的任务、Run、目录和调用。停止仍在执行的 Run 后，点击 **核验退出并恢复**：

1. 服务端读取启动前已登记的执行身份，核对对应 runner 的终态回执。回执必须匹配 Run、attempt、call 和随机回执身份，且证明未启动目标，或整个 Job 已无活动进程。
2. 没有可靠回执时，核验操作请求遗留 runner 停止。稍后再次点击核验可读取其最终退出回执；发出停止请求本身不算退出证据。
3. runner 崩溃或回执损坏时，重启 **Windows** 后再次核验。服务端比较同一机器的内核启动 GUID，证明旧启动中的进程已退出；仅重启 Gateway 或应用不能提供这项证明。
4. 旧版本遗留 Run 没有预登记执行身份时，第一次核验先登记本机启动基线并保留屏障，再按提示重启 Windows、重新核验。系统启动信息读取失败时不会放行。

每个未清理调用都必须通过核验。随后在一个事务内保存核验记录、移除清理屏障、结算 Run 与派发、释放租约、登记原有结算 outbox。重复点击返回同一结算身份；事务失败可再次核验，不会留下只解除屏障而未完成结算的中间状态。

恢复后的 Run 仍为 `interrupted`。工具的执行 claim 和结果不被改成成功，恢复不会自动重放命令，也不把进程退出等同于副作用已撤销。请核对目录内容及其他实际副作用后，用新调用明确继续。

回执存放在本机用户的 `%LOCALAPPDATA%\Focus\shell-receipts`，不随工具调用结束删除。核验记录保存在 `Run.workspace_result.shell_cleanup_recovery`。API 使用现有 loopback 与 `X-Focus-Session` 保护：

- `GET /desktop/api/shell-recovery`：列出受阻 Run 和目录。
- `POST /desktop/api/runs/{run_id}/shell-recovery`：使用服务端证据核验并幂等结算。客户端不能提交路径或清理结论来解除屏障；证据不足或执行器仍运行返回 409。

进程退出只能证明本次本机进程树结束。恢复不推断外部系统操作是否完成，也不把工作区指纹相同标记为可自动重试。
