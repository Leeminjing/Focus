# Desktop 领域重构

基线：`60c5eef`。目标是按功能定位实现，并保持原有接口、数据库结构、Loop 决策和执行行为。

## 本次调整

- 根目录只保留模块标记和 `app.py`；其余实现按领域归入 13 个包。
- 混合路由拆为 system、workspace、conversation、context、capability、patrol、run、agent、material 接口模块；`api/routes.py` 只注册路由。
- 主运行受理编排归入 `runs/intake.py`，路由只解包请求及依赖；引用授权、Loop 分流、重放幂等和派发通知沿用原有顺序。
- SQLAlchemy ORM 和 Pydantic 请求模型分别放入 `persistence/models.py` 与 `api/schemas.py`；共享存储常量位于 `persistence/contracts.py`。
- `DesktopService` 保留调用接口并装配资源，110 个业务操作由 13 个有明确依赖端口的模块实现。运行准入、恢复、装配、权限上下文、Agent 工厂和结算分别维护。
- 工作区材料查询、冻结附件读取和删除事务归入 `materials/workspace_service.py`；文件链接、版本选择、授权与文档预览归入 `workspaces/`。
- Agent Loop 的根目录从 150 个文件收敛为 11 个入口；支撑机制按事实、观察、完成判定、任务、投影、恢复、执行、输入、资源、生命周期等职责分组。
- 更新后端、插件、迁移注册、测试、脚本和文档中的导入与源码路径。没有保留旧根目录的转发文件，也没有改写历史迁移的 DDL。

## 保持的约定

`contexts/curation/` 和 `contexts/curator/` 分开维护。材料文件生命周期与逐轮运行材料保持不同归属。原有 Context、Run、dispatch、Loop 及协作的数据库表、字段、约束和索引沿用既有定义。

领域依赖 `Protocol` 端口而不是 `DesktopService` 类型。当前组合根适配这些端口，保留既有事务及测试可注入行为；领域实现也可以用满足端口的其他适配器单独构造。组合入口继续协调共享的运行状态和后台任务生命周期。

同名的插件 `DeployRequest` 与桌面请求必须继续得到各自的 OpenAPI 组件。`api/openapi.py` 在接口装配时固定这两个已发布的组件名称和引用，避免移动模块或改变注册顺序影响客户端；Python 模型保留真实的模块归属。

除目录和职责迁移外，修复了 `_governed_context` 的一个既有缺陷：工具执行账本的延迟脱敏回调使用 `configured_secret_values`，原方法所在模块缺少可见的导入，实际文件采集可能触发 `NameError`。新实现显式导入该函数；回归经真实上下文装配和账本创建文件采集器，确认秘密值在前后快照中被替换。

## 验收

验证分为三类：迁移前后的完整 OpenAPI 对比；注册后的 PostgreSQL 建表与索引 DDL 对比；现有行为回归和领域依赖检查。源码结构断言迁移到新的实现位置，保留原有权限、准入、恢复和终态写入约束。

运行后端测试时，将 `backend/packages/harness` 和 `backend/tests` 加入 `PYTHONPATH`，使用仓库现有的隔离 PostgreSQL fixture。测试报告中的既有失败需要在独立 `60c5eef` 副本复现，不能仅凭断言路径变化判断业务回归。
