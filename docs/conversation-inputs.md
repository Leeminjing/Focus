# 普通会话：运行中补充和下一轮排队

普通单线程会话运行时，发送按钮变为“补充当前轮”，旁边提供“排队下一轮”。Enter 与发送按钮一致。

- 补充绑定提交时的 Main Run，先显示“已受理，等待当前轮继续”。消息耐久进入精确上下文后显示“已进入当前轮上下文”。这不表示模型已完成要求。
- 在工具开始前发现补充时，先闭合旧工具调用，让模型读补充后重新决定操作。已经开始执行的工具不会因补充自动撤销。
- 模型输出最终答案期间收到补充时，继续当前轮处理；收尾间隙未能交付的补充显示“本轮结束前未送达”，不会自动改投新 Run。
- 补充支持文字；新增材料或技能需选择下一轮排队。补充不会改变当前轮的执行权限、模型或冻结装备。
- 排队消息保存在后端，按任务内受理顺序发送，每条消息启动一轮。当前轮成功且清理与结算完成后才允许启动队首。
- Run 收尾遇到暂时故障时，按 1、2、4、8、16、30 秒退避重试，此后每 30 秒继续尝试。原始运行记录保留至结算成功；同步任务意外退出由后台派发循环接管。恢复只调用幂等 finalizer，不重放 Agent；结算完成后唤醒队列。服务关闭会停止重试，数据库中未结算的 Run 仍由现有启动恢复处理。
- 当前轮报错、中断或等待审批时保留队列并暂停，不自动跨过审批。用户可撤回编辑或删除；暂停队首处理前后续条目不越过它。
- 待发送和暂停的队列消息都允许删除，或撤回到输入框编辑后重新排队。输入框已有草稿或附件时先提示处理，避免覆盖。
- 原请求的内容、模式、目标 Run 和幂等身份共同冻结；网络回执丢失时按原身份重试。队列启动后不允许撤回。

后端入口为 `POST /desktop/api/tasks/{task_id}/main/inputs`，接受 `mode`、可选 `target_run_id` 和 `run: MainRunCreate`，并要求 `Idempotency-Key`。GET 同路径读取状态，DELETE `/{input_id}` 撤回尚未启动的队列消息。

验证：`python -m pytest backend/tests/test_conversation_inputs.py -q`、`node --test desktop/src/renderer/features/conversation/conversation-inputs.test.cjs`、`node desktop/tests/e2e/conversation-inputs.e2e.cjs`。
