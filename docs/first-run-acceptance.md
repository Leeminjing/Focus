# 首发验收：干净 Windows 安装后的第一次真实任务

本项是首发发布门槛。自动化中的合成凭据、HTTP 模拟响应及客户端构造通过，不能替代本项真实服务验收。

## 安装与首次配置

1. 在干净 Windows 用户环境中运行安装器，不预先手工编辑 `.env` 或 `config.yaml`。
2. 运行 `focus`。桌面应正常启动并自动打开「设置 → 模型」，标明密钥未设置或仍为占位值。
3. 填写可用服务的真实 API Key，核对地址、模型名称、Provider、API 协议与策展输出方式，指定普通及策展默认模型。
4. 点击「保存并立即生效」。等待普通调用和策展输出两项验证通过；策展验证必须使用实际配置的输出方式并能编译为有效上下文。
5. 验证通过后自动收起工作台、回到机器人输入面板并打开项目文件夹选择器。取消选择时，应保留「选择项目文件夹」入口；重选并绑定文件夹后，提示输入第一个目标，点击发送或按 Ctrl+Enter，确认收到真实模型回复。随后执行一次 Context 策展并确认产生可用的上下文。
6. 在验证失败、未验证即退出、取消文件夹选择后退出三种情况下分别重启，应继续对应步骤；验证失败不能进入文件夹选择，也不能自动发送目标。
7. 完成配置与文件夹绑定后退出并重新启动，应继续只显示轻量机器人入口，确认凭据仍可用，再次完成普通请求。记录安装版本、Windows 版本、模型名称、协议、输出方式与验证时间，不记录密钥。

## 凭据轮换与错误恢复

| 场景 | 验收结果 |
| --- | --- |
| 保留发行模型全部字段，仅在密码框填写新 Key 后保存 | 下一次模型请求及策展请求均使用新 Key，无需重启；发行配置没有被复制成用户覆盖项 |
| 删除必需密钥变量或保留安装模板占位值 | Gateway、桌面与设置 API 可用，自动打开模型设置并提示填写真实凭据 |
| 模型目录字段错误或默认模型未声明 | 仍可打开设置，能编辑原始条目或恢复发行目录并保存修复 |
| 密钥错误或无权限 | 提示 401/403 及更换密钥、开通权限等对应操作；修复后可重新保存验证 |
| 地址/路径、模型名称或协议错误 | 根据服务返回信息提示检查对应字段；404 无法区分模型和路径时明确要求同时核对 |
| 网络断开、代理错误或超时 | 有时间上限并提示检查网络、代理、地址；恢复后可重新保存验证 |
| 普通调用成功但策展返回无效内容 | 清楚显示策展输出失败，指导检查输出方式、模型及协议，不能显示完整验证通过 |
| 凭据或配置文件写入失败 | 返回保存失败，恢复旧文件、环境变量与运行配置 |

保存成功与联网验证成功分别呈现。联网失败时已保存的配置仍可编辑，点击保存会重新验证。每次保存会发出普通调用和策展调用，消耗相应服务的少量用量。启动时不会自动进行模型请求。

`FOCUS_MODEL` 是优先于面板默认选择的启动环境覆盖项；设置页显示该覆盖。若它指向不存在的条目，须清除/修改启动环境中的 `FOCUS_MODEL`，或在设置中增加匹配的条目。

## 自动化覆盖

- `backend/tests/test_model_settings.py`：仅轮换凭据后，用真实模型工厂检查每个共享条目取得新 Key。
- `backend/tests/test_model_setup.py`：真实 SDK 请求序列化与策展引擎，HTTP 传输使用合成响应；覆盖 Chat Completions / Responses 及三种输出方式、故障诊断、脱敏和保存回滚。
- `backend/tests/test_model_settings_api.py`：真实 Gateway 与隔离 PostgreSQL，验证缺失/占位凭据和损坏模型目录的启动、读取和修复。联网能力在上一组测试中验证。
- `desktop/model-settings-ui.test.cjs`：自动打开模型设置、预选编辑条目、保存结果与失败提示、重复刷新保留未保存密钥。
- `desktop/desktop-patrol-host.test.cjs`、`desktop/first-run-settings.test.cjs`、`desktop/desktop-patrol-refresh.test.cjs`：首次路由、验证失败门禁、中断恢复、取消目录选择后的重试与第一次显式发送。
- `desktop/first-run-ui.test.cjs`：真实 Electron 加载生产工作台、preload 和机器人面板，经隔离 HTTP 验证失败/成功及目录取消/重选后，走到第一次发送；不使用真实 Provider 或系统目录选择器。

## 文件阅读与回答链接

| 场景 | 验收结果 |
| --- | --- |
| 从文件 / 产物抽屉、LoopFact、机器人引用详情查看同一文件版本 | 都使用共享阅读器；PDF 可翻页，文本可查找、复制，保留系统打开、另存入口 |
| 回答正文的 `reports/report.md`、中文及空格路径、百分号编码路径 | 从原始 href 解码一次，按回答所属任务、Run、工作树定位；失败时显示原因 |
| 两次执行在不同工作树生成同名文件，之后继续执行或派生 Context | 旧回答保留原生产 Run；不能使用当前最新执行位置代替旧来源 |
| 查看旧文本快照；查看磁盘已变化的旧 PDF | 旧文本保持冻结；旧 PDF 字节不匹配时说明历史内容不可用，只有显式“打开当前文件”才读取当前版本 |
| 旧消息缺少可信来源，或多个来源冲突 | 显示来源不可验证，可从文件 / 产物选择；不猜测同名文件 |

来源投影只读取已提交 revision 的谱系和服务端 Run，不采信正文自行声明的文件来源。谱系查询每页缓存，并限制深度 32、来源版本 64；超限同样显示来源不可验证。

自动化覆盖：`desktop/artifact-drawer.test.cjs` 的二进制 PDF 入口回归、`desktop/desktop-patrol-refresh.test.cjs` 的正文链接和失败提示、`desktop/desktop-patrol-ui.test.cjs` 的真实 Electron 翻页/中文空格链接/原生操作、`backend/tests/test_conversation_file_sources.py` 的跨执行与派生来源，以及 `backend/tests/test_file_link_identity.py`、`backend/tests/test_file_preview.py` 的实际路径与版本校验。Electron 使用隔离 HTTP fixture；它不替代安装包的真实文件验收。
